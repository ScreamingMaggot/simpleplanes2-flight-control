## v0.2 高度环（已上盘 2026-09-25，待飞）

**分层照 Droplet**：面板=律（6 条），零件=分配（每零件一行，引用面板名）。

| 面板 setter | 式 | 含义 |
|---|---|---|
| `boot` | `clamp01(Time * 0.25)` | 软启动（保留） |
| `cmdPhi` | `-60 * Roll` | 坡度指令（纯杆量，本版不动） |
| `vs` | `rate(Altitude)` | 爬升率真源（**必须排在用它的 setter 之前**——app7 引用闸抓到过顺序错） |
| `altTgt` | `smooth(Altitude, ((abs(Roll)>0.05) \| (abs(Pitch)>0.05)) ? 9999 : 0.5)` | **松杆即锁定当前高度**；动杆时冻结（冻结原语正用法，替代记忆/锁存） |
| `vsCmd` | `clamp(0.25 * (altTgt - Altitude), -5, 5)` | 爬升率指令（能量弱：±5 m/s 上限） |
| `cmdThe` | `min(-30 * Pitch + 0.8 * (vsCmd - vs), (IAS < 45 ? 8 : 90))` | 俯仰指令 = 杆量 + 爬升率误差；保留失速门 |

零件：副翼 `0.010*(RollAngle - cmdPhi) + 0.004*RollRate`；升降舵 `0.040*(PitchAngle - cmdThe) - 0.007*PitchRate`；两者 `Activate7 ? … : 原生`。
读数：左 `{IAS}m/s {AGL}m`；右 `A7{±1} vs{实际}/{指令}`。

**判据（一局）**：① 松杆平飞 → 高度稳住、`vs`/`vsCmd` 都趋 0，100 m 偏差在 30~60 s 内吃掉；② 拉杆爬 200 m 后回中 → 新高度成为新目标（不被拽回旧高度）；③ 带杆时内环权限不受外环削弱；④ `vsCmd` 显示不超 ±5；⑤ 若出现周期 >5 s 的俯仰慢振 → 先降 0.8、再降 0.25。
**失效模式**：面板若整块死 → `cmdThe/cmdPhi`=0 → 飞机自己压成平飞（不是失控），拨掉 7 号即回原生手动；面板里**没有 `ActivateN`**（安全设计）。

## v0.2b 定高（无记忆版，已上盘）— 以及 `smooth` 语义存疑

**app9 回滚（我在 app8 误判）**：用户给出**两个工况对照**——满油门 `vs 0 / 指令 −2~−3`（收敛 ✓）、怠速 `vs −6 / 指令 +5`（饱和）。⇒ **v0.2 本身是好的**；怠速那条是**推力不足**（怠速守不住高度，环在尽力要爬升，饱和属正常），不是 `smooth` 语义错。我此前拿怠速单点就下"原语坏"的结论并拆掉 altTgt，是误判，已恢复 v0.2（面板回到 6 条）。`smooth(x,r)` 的语义**仍是未标定项**（不禁止使用，但别在关键处依赖它到"知道它到底怎么变"的程度）。读数改为 `A7 {指令}/{实际}` 便于对照。

**（作废的）app8 判断**：：飞机以 −6 m/s 下沉时指令 `vsCmd` 饱和在 +5 ⇒ `altTgt`（`smooth(Altitude, 0.5)` 那个"松杆抓当前高度"）越落越远 ⇒ **`smooth(x, r)` 的第二参数不是我理解的"时间常数"**（若按 τ=0.5 s，滞后只有 ~3 m，不可能把指令顶到 ±5）。该原语言义**另案标定**（自证实验设计：显示 `smooth(100,1)` 在 t≈2 s 与 t≈10 s 的值就能分开"指数滞后"与"限速跟随"）；**在标定前不要在任何律里依赖它**（原语 #2 的"冻结锁存"用法因此撤销待验）。

**v0.2b 的替代设计（更简单，且不需要记忆）**：定高本质 = 把爬升率压回 0。
- 面板 4 条：`boot` / `cmdPhi = -60*Roll` / `vs = rate(Altitude)` / `cmdThe = min(-30*Pitch - 0.8*vs, (IAS<45 ? 8 : 90))`
- 语义：**杆量给姿态（±30°），`-0.8·vs` 把松杆时的残余爬升/下沉压回 0** ⇒ 松杆即定高；带杆即压过它。
- 读数右：`A7{±1} vs{实际}`。
**判据**：① 松杆平飞 → `vs` 收敛到 0（±1 m/s 内）、高度稳住；② 带杆 ±30° 姿态权限不受影响；③ 无周期 >5 s 的俯仰慢振（有则先降 0.8）。

## v0.3 高度环（官方定义校正 + 有界积分，已上盘）

**两条原语官方定义（functions/smooth、functions/sum 页，权威）**：
- `smooth(x, rate)` = **每秒最多变化 rate**（限速跟随）；⇒ **"冻结"要用 `rate=0`**（我 v0.2 写成 `动杆?9999:0.5` = 极性反了，这才是"松杆时目标被甩在身后、指令顶死"的真因）；
- `sum(x)` = **∫x dt**，帧率无关，从关卡加载起积分（用户实机 `sum(1)` 每秒 +1 先行证实）。

**面板 9 条**：`boot` / `cmdPhi` / `vs` / `altTgt(smooth(Altitude, 动杆?9999:0))` / `vsLim(IAS>42?20:5)` / `vsCmd(0.25·高度误差)` / `vsErr` / `vsInt(clamp(sum(松杆?vsErr·K:0), ±8))` / `cmdThe(min(-30·Pitch + 0.8·vsErr + vsInt, 失速门))`。
**积分抗 windup**：FT 的 `PID(...,i,...)` 内部无抗饱和 ⇒ 自己用 `sum` + **外部 clamp(±8°)** + **仅松杆时积分**（不动杆时不积，免得与杆量打架）。
**读数**：左 `IAS/高度`；右 `A7 指令/实际 I积分`。

**判据**：① 平飞松杆 → 实际收到 0.0，`I` 停在非零值稳住；② 爬升后回中 → 新高度成目标，`I` 小幅回摆后稳住；③ `I` 来回摆/俯仰慢振 → K 减半（0.3→0.15）。
**app11 调参**：用户判"收敛太慢" ⇒ K 0.08→0.3（≈4×）；若仍慢，另一根旋钮是 P 项 0.8→1.2。

## v0.3.3：外环门控（用户实测"手操时也有 ±20 俯仰限制"）

**病因（我的设计漏项）**：`cmdThe = -30·Pitch + 0.8·vsErr + vsInt` 里，后两项**不随杆量让位**：
- `0.8·vsErr` 恒在出力 —— 拉杆爬升时 `vs>0` 立刻反向拉回，`vs=25 m/s` 时该项正好 **20°**（用户感觉到的"±20 墙"就是它）；
- `vsInt` 手操时虽不累积，但**冻结着上次的值继续顶**（≤±8°）。
另：`vsLim=±20` 只限制外环要求的爬升率，不直接限制俯仰（数字撞巧）。

**修法**：外环整体加门控并 0.5 s 淡入淡出（用刚标定的 `smooth` 限速跟随）：
`hold = smooth(动杆 ? 0 : 1, 2)`，`cmdThe = min(-30·Pitch + hold·(0.8·vsErr + vsInt), 失速门)`。
⇒ **带杆=纯杆量全权限（±30° 俯仰 / ±60° 坡度），松杆=外环 0.5 s 内接管定高**。

## app20：方向舵阻尼加强被否（回滚）

**改了什么**：方向舵从原厂 `clamp(Yaw − 0.04·YawRate)` 改为接通后 `clamp(Yaw − 0.10·YawRate)`（2.5× 阻尼，意图"Yaw 参与航向稳定"）。
**结果**：用户报"**相当抖**"⇒ 立即回滚到原厂式（两条分支同形=等于没改）。
**结论与纪律**：该通道**不是"加大增益就行"**。试图用飞行数据反推符号也**不成立**——方向舵命令是**内生量**（在偏航动力学内部），`corr(yr, d(yr)/dt)` 之类的回归无法分离它的作用（本次算出 +0.15 偏向"阻尼"，与实际体验矛盾，正说明该方法无效）。
**下一步（待用户点头）**：一局**已知舵步标定**——临时 `RUD = GATE ? (Time > 30 ? 0.4 : 0) : 原式`，从 TEL 的 `yr/hr/aos` 同时读出 ①正舵=左/右偏 ②舵量→偏航率权限（°/s per stick）③侧滑响应方向；然后按实测数字写阻尼/协调项。在此之前**不动方向舵通道**。

**结论**：航向保持 PASS。横风下的稳态侧滑（−8.5°）不是故障，是"发动机头指向"这条语义的必然结果；要"压线飞"需另做**地速航迹环**（`rate(Latitude)/rate(Longitude)` + `deltaangle` 对目标航迹）。

## v0.5：航迹保持（B 方案，用户点名"为后续自动起降打基础"）
