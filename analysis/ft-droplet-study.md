# Droplet.splane 解剖（用户给的 FT 强例，2026-09-25）

载体：`Crafts/Droplet.xml`（39.5 KB，26 setter，10 IC）。零件构成：`Fuselage-Body-1`×24、`Engine-Jet-1`×10、`Wing-2`×4、**`Label-1`×3**、`FlightComputer-1`×1、`Fuselage-Inlet-1`×1、`Camera-1`×1。
一句话定性：**这是一架"纯 Funky Trees 全权限飞行计算机"**——9 台喷气发动机当矢量推力阵，FT 面板里跑完整的世界系位置-速度控制律 + 姿态内环 + 地形规避 + 攻击弹道 + 雷达式文本显示，**零 Lua**。

## 1. 控制架构（读法）

```
目标/玩家输入
   ↓  tLAT/tLGT/tALT  ← 目标世界坐标（极坐标→经纬度）
   ↓  vALT/vLAT/vLGT  ← 世界系速度指令（含地形项 terrain）
   ↓  X,Y,Z = PID(速度指令, rate(经/纬/高), 0.1, 0, 0.005)   ← 世界系力分量
   ↓  relX,relY,relZ  ← 3-1-3 欧拉旋转矩阵（Heading/RollAngle/PitchAngle 全展开）
   ↓  混控到 9 台发动机 IC（±relZ 升力、±relX/±relY 侧力、±aRoll/±aPitch 力矩）
   ↓  min=0 max=0.1 把混控值映射成推力份额
姿态内环另走：aPitch/aRoll/aYaw = PID(姿态/迎角/侧滑目标, PitchRate/RollRate/YawRate, …)
```

**手动模式也是电传**：`vLAT/vLGT` 的 else 分支 = `Throttle*cos(PitchAngle)*cos/sin(Heading)*(2000+1000*Activate4)` —— 玩家推杆/油门给定的是**速度矢量**，不是舵面。这就是"把飞机变成操纵杆直接指挥力"的做法。

## 2. 可复用原语（8 条，全部来自原文，可直接抄）

| # | 原式（节选） | 是什么 | 能顶掉我们哪段 Lua |
|---|---|---|---|
| 1 | `start = clamp01(Time*0.25)` | **上电软启动斜坡**：前 4 s 从 0 线性放行，避免初始瞬态打满舵 | SC-5 里我用 `smooth(ENG?1:0,0.35)` 做软接合，这条更干净可控 |
| 2 | `smooth(x, 9999*clamp01(-tChange))` | **`smooth` 的 rate 当"冻结开关"**：rate→9999 时输出≈保持旧值 ⇒ **无自参照的锁存器** | 我们缺的原语（BT 黏滞、TRV 捕获旗标、GA 锁存全都卡在这） |
| 3 | `tChange = smooth(clamp01(TargetSelected), 3+97*clamp01(TargetSelected)) < 0.01` | **事件沿检测**（目标切换瞬间翻转）：用同一冻结技巧造出"上一拍"比较 | SC-2/SC-5 里所有"状态改变沿"判据 |
| 4 | `tLAT = Latitude + TargetDistance*cos(TargetElevation)*cos(TargetHeading)`；`tLGT = …sin(TargetHeading)`；`tALT = Altitude + TargetDistance*sin(TargetElevation)` | **目标极坐标→世界坐标**，只用 FT 内置变量 | **直接推翻我 SC-2 的"目标位置拿不到"结论**（见 §3） |
| 5 | `rate(Longitude)/rate(Latitude)/rate(Altitude)` = 世界系速度三分量（该游戏经纬度单位是米） | **不用 GS/Heading 分解的速度估计**，还能 `rate(tALT)` 求目标速度 | SC-3b 里我手工分解地速的段落 |
| 6 | `terrain = …+ clamp01(AltitudeAgl<100)*clamp(rate(Altitude-AltitudeAgl), …, 8000)` | **`rate(AMSL−AGL)` = 地形沿迹抬升率**，直接当地形前瞻项加进垂直速度指令 | SC-1 v6 的 Lua 前瞻（`trate=LPF(d(alt)/dt−d(agl)/dt)`）在 FT 里一行就有 |
| 7 | `relX/relY/relZ`（把 3-1-3 欧拉矩阵整式展开） | **世界系→机体系变换**，纯三角函数拼装，无矩阵库 | 任何"多执行器混控"（矢量喷口/差动刹车/螺旋桨推力分配） |
| 8 | `size = repeat(smooth(Time*3,sizeSpeed),2)-1`、`alpha1 = floor((1-rSize)*128/16)`、`alpha2 = floor((1-rSize)*128-alpha1*16)`，再喂进 `Label-1` 的 `designText`：`{rate(Fuel)=0.0&GS=0.0 ? "○" : ""}<alpha=#{alpha1>=10?"C":…}` | **文本显示也是 FT**：Label 的 `designText` 里 `{表达式}` 会被求值，还能**把数值按 16 进制拆两位编码成颜色**画雷达扫描 | 见 §3 第 2 条——这解决"UI 看不见零件值" |

## 3. 对本项目既有结论的三条订正（都推翻我自己记过的东西）

1. **SC-2「目标位置不可达、CLR 判死 ⇒ 只能把锁定锥当信标」= 错**。原语 #4 说明：`TargetDistance/TargetElevation/TargetHeading` 三个内置量就足够解出目标的世界经纬度与高度，纯 FT 可达。当年该走这条路，我却在 CLR 上烧了几局。
2. **「零件级 FT 的值在 UI/遥测里永远看不见」（§30）要限定范围**：遥测列和原厂仪表确实绑手柄轴，但 **`Label-1` 的 `designText` 里可以直接引用 setter 面板变量**（本例 `alpha1/alpha2/size` 全是 setter 名，且被正常求值）。⇒ FT-Lite 完全可以在座舱里挂一行 `PWR {TDE*100}%  SD {SD}  LT {LT}`，把"律在想什么"显示给玩家——这正是我缺的观测通道，且不需要 Lua。
3. **同名 setter 重复定义合法，且后定义者生效**：本例 `sizeSpeed` 出现两次（`2` 与 `clamp(GS,100,1000)/(500-0.4*clamp(GS,100,1000))`），面板照常工作 ⇒ 面板顺序=求值顺序、同名后写覆盖，这条与"priority 仲裁"记录一致，但**重复名**这个用法我以前当成风险避开了。

## 4. 与 §32/§33 的关系（不冲突，是补全）

- 本例的推力阀门是 **`Engine-Jet-1` 的 IC**（喷气件=推力件，直接吃表达式）；我们那架星型活塞机的推力阀门在 **`PropellerAssembly` 的 IC**，发动机 IC 只改转速/油耗。**结论统一为一句：阀门件随推进器类型而变，必须逐零件类型确认，不存在"油门通道"这种通用件**（矩阵 §1 已分列）。
- 起落架仍属"只认裸轴名直接绑定"的一类（本例没有可收放起落架的表达式写法可学，Droplet 的 `Fuselage-Body` 全是硬结构）。

## 5. 下一程怎么用这份材料

1. 造最小载体时**照抄它的分层**：世界系外环（位置→速度 PID）+ 欧拉变换 + 执行器混控 + 姿态内环，四层各自可单测；
2. 把原语 #1/#2/#3 先做成**单通道自证实验**（一次一架次）：软启动斜坡、`smooth(x,9999)` 冻结锁存、事件沿检测——这三个一旦确认可用，SC-5 当年卡住的"黏滞/锁存/捕获旗标"全部有解；
3. 观测通道改用 **`Label-1` designText**（原语 #8），不再依赖 Lua 遥测就能在驾驶舱里看到律的内部量；
4. SC-2 狗斗律回头补一条：用 #4 把目标世界坐标算出来，导引律就能拿到真几何（不再是信标锥）。

## 6. 展示局实测（app80，Droplet-TEL，70 s，图 `figures/droplet-demo-report.png`）

为读数临时给复制体挂了 `MFD-1`（原 `Droplet.xml` 未动）。观测（14 Hz 遥测）：

| 量 | 值 |
|---|---|
| 峰值地速 | **2722 m/s**（IAS 表 2492） |
| 最高高度 | 3998 m |
| **空中定点保持** | t≈52~58 s，**GS 中位 0 m/s @2037 m**，纯 FT 位置环站住 |
| 指令性刹车 | t=15→17：937→111 m/s（≈1 s 掉 830）；t=51→52：2720→12 |
| 玩家输入 | 油门杆 67% 活动、俯仰 10%、横滚 8% ⇒ 基本靠**油门杆当速度指令**在飞（电传 else 分支） |

**数据卫生**：这量级下游戏气动（`aerodynamicsModel="Legacy"`）与传感器已失真——`gf` 出现 181/576/844/985 的尖峰、静止时 `aoa` 乱跳 ±170°。**性能可信，别拿这些帧做物理标定素材**（做辨识要挑常规速度段）。

## 7. 对我们三个已封课题的直接含义

1. **瓶颈从来不是 FT 的表达能力**，而是①机体推力/舵量，②我没掌握的原语。现在原语齐了：软启动斜坡、`smooth(x,9999)` 冻结锁存、事件沿检测、世界系位置-速度串级、3-1-3 欧拉变换、`rate(AMSL−AGL)` 地形前瞻、Label 文本观测。
2. **SC-5 当年缺的"等待航线消高"有解了**：位置环（悬停/定点）+ 缓慢降高指令 = 纯 FT 的盘旋/程序等待，不需要 Lua，也不需要自参照。
3. **SC-2 的导引可以升级**：原语 #4（目标世界坐标）+ 位置串级 = 从"锁定锥信标追踪"变成真正的几何导引。
4. **手动超控可以更干净**：把杆量当**速度/姿态指令**而不是舵面偏度（它的 else 分支做法），比我们在 SC-1 用的 trim 叠加超控层次更清楚。


## 8. 写法对照：人家怎么落 XML / input，我为什么老失败

| 维度 | Droplet 的写法（原文可查） | 我在 FT-Lite 的写法 | 教训 |
|---|---|---|---|
| 面板规模 | **26 条 setter**，每条一个物理含义，名字说人话（`terrain/strike/tALT/relX/aPitch`） | **115 条**，其中 117 条是脚本生成的走廊链（`QS7/QL12/G9`） | 面板是"思路的目录"，不是编译产物。生成器堆出来的量级直接把可读性与可查错性归零，（★2026-09-26 更正：此处"长式子=整面死"作废——app59 死因是前向引用 `Name not defined: BTp`，与本条无关；见 platform-facts §27 更正） |
| 量程处理 | 交给 IC 属性：每台喷气 `min="0" max="0.1"`，**式子里保持物理原值**（`clamp(-relZ,0,10000)+aRoll+…`） | 我在式子里一路 `clamp(…, -1, 1)`、`clamp(…, 0, 1)`，式子越写越长 | 文档早就写了 min/max 是**映射**——缩放该交给属性，式子只写物理 |
| 执行器分配 | **一个零件一条短式子**，靠符号与位置表达阵列（`relX+aYaw` / `-relX-aYaw` / `relY` / `-relY`…） | 用程序生成"选择链"把 13 条跑道塞进面板里硬算 | 阵列/对称是 XML 的强项（每零件显式一行），不是表达式的强项 |
| 二阶耦合 | 主动补：`+0.5*abs(aPitch)`（抬头时两侧差动）、`Roll*(150+clamp01(FireGuns)*300)`（坡度→偏航前馈） | 我一律"先跑起来再调增益" | 先想清物理再落式子；调出来的增益是债 |
| 状态与记忆 | 三件套内置函数解决：`clamp01(Time*0.25)` 软启动、`smooth(x, 9999*flag)` 冻结锁存、`smooth(clamp01(sel),3+97*sel)<0.01` 事件沿 | 我拿 `smooth(ENG?1:0,0.35)` 硬凑软锁存，还因为想写自参照锁存烧掉整面（app59） | 需要的原语平台都有，是我没找 |
| 逻辑写法 | 数值域里做逻辑：`Activate1&(TargetSelected \| -tChange)`、`*Activate4`、`clamp01(-Activate3)` | `(((Activate7 ? 1 : 0) > 0.5) & HLD)` 这种又长又踩 bool→−1 的写法 | 布尔在 FT 里就是数：`-A` 取反、`A&B` 与、`A\|B` 或，直接写 |
| 观测通道 | `Label-1` 的 `designText` 里塞 `{表达式}`（连 setter 名都能引用） | 我把诊断挂在遥测轴列上（§30 瞎仪器），连测三局 | 律在想什么，机体自己就能显示出来，零 Lua 依赖 |
| 分层 | 三层分明：面板=外环律；零件 IC=混控/分配；Label=显示 | 全塞面板 + 4 条零件式，混控与律混在一起 | 分层错了，查错就无从下手 |

**一句话总结我这几局的失败原因**：我把 FT 当"能用代码解决就写代码"的目标平台，人家把它当"每个零件显式写一行物理"的电路来画。XML 是原理图，不是编译器。
